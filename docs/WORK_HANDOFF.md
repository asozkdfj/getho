## 브랜치와 수정 범위

- Codex 작업 브랜치: `codex/model-qa-contract`. 별도 checkout `getho-model-qa`에서 작업한다.
- 기존 보고서 브랜치: `codex/qa-latest-ui-review`. 현재 기준 커밋은 `36715b2`다.
- Claude 브랜치 제안: `claude/fatigue-features-v1`. 아직 이쪽에서 생성하지 않았다.
- Claude는 최신 QA 브랜치를 fetch한 뒤 출발 커밋과 문서를 확인한다. 기존 개발 브랜치에 반영할 경우 차이를 먼저 검토한다.
- Codex는 `scripts/qa/check_prediction_contract.py`, 대응 테스트, QA 문서를 담당한다. Claude는 신규 특성·공급자 어댑터·후보 모델을 담당한다.
- 공유 ML 평가 파일을 수정해야 하면 담당 기록에 범위와 인터페이스 변경을 먼저 남긴다. 다른 담당의 작업을 덮어쓰거나 같은 checkout에서 브랜치를 바꾸지 않는다.
- 각자 자기 기록 파일만 갱신한다. 이 진입점은 통합 시 갱신한다. 완료는 커밋·검증 결과가 기록됐을 때만 표시한다.

## 개발·인계 순서

1. [Claude 상세 프롬프트](qa/CLAUDE_MODEL_IMPROVEMENT_HANDOFF.md)와 [예측 교환 계약](qa/PREDICTION_CONTRACT_V1.md)을 읽는다.
2. Claude는 데이터 가용성·출처·시각·결측률을 확인하고 피로/휴식 변수군 한 묶음을 구현한다.
3. 동일 경기의 기준/후보 확률과 변수 근거를 JSONL로 출력하고 계약 검사를 실행한다.
4. 기록에 기준 커밋, 결과 커밋, 명령, 수치, 한계를 적고 push한다. 사용자에게 해당 브랜치·커밋을 전달한다.
5. Codex가 결과를 받아 누수·표본 제외·성능·회귀를 검토한다. 계약 검사 통과만으로 성능 개선이나 배포를 승인하지 않는다.
6. 통합 담당자가 검토된 변경을 병합하고 통합 테스트한다. main 병합·배포는 이번 준비 작업에 포함하지 않는다.

## 환경

계약 검사와 테스트는 Python 표준 라이브러리만 사용한다. 추가 설치가 필요 없다. 전체 ML 테스트에는 저장소 의존성과 pytest가 필요하며 기존 프로젝트의 `uv.lock`/`pyproject.toml`을 따른다. 로컬 `.qa-deps` 및 원본 데이터 캐시는 Git에 올리지 않는다. 다른 환경에서는 자동으로 존재하지 않는다.

이 문서가 자동 동기화·자동 메시지·예약 실행을 만들지는 않는다. Git fetch와 사용자/담당자의 인계가 필요하다.
