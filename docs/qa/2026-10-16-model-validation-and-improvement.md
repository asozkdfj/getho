# 추론 모델 검증 및 성능 개선 QA 리포트

검토일: 2026-10-16 KST · 기준 커밋: `01821b9` · 대상: EPL Edge Lab v0.2.0

## 1. 최종 판단

**현재 모델은 유지하고, 이번에 보강한 평가 도구를 다음 모델의 비교 기준으로 사용한다.** 기본 비율 대비 예측 신호는 재현됐지만, 새로운 확률 앙상블의 개선은 채택할 만큼 크거나 확실하지 않았다. 이번에 완료한 개선은 평가 시점 통제·재현성·오차 분석이다. 운영 예측 정확도가 향상됐다고 주장하지 않는다.

기존 Sol 작업의 보고서를 참고하되, 이번에는 실제 원본 EPL 8개 시즌 3,040경기를 내려받아 검증 1,140경기와 시험 1,140경기를 다시 계산했다. 기존 방식의 운영 모델 log loss **0.9831743008593544**를 저장된 보고서와 동일하게 재현했다. 원본의 시즌별 팀 수·경기 수·대진 중복 검사도 통과했다. 자료의 사실성을 다른 공급자와 대조한 것은 아니다.

Docker, 운영 DB, 실서비스는 실행하지 않았다. 10개 리그 전체·명단 모델은 이번에 재실행하지 않았으며, 해당 내용은 이전 보고서와 구분했다. 최초 보고 시 코드 변경은 로컬 작업 트리에 있었다. 이후 사용자 요청에 따라 Git 전달 자료로 준비했으며, 배포·모델 버전 변경은 하지 않았다. [Claude 전달 프롬프트와 후속 방향](CLAUDE_MODEL_IMPROVEMENT_HANDOFF.md)을 함께 참고한다.

## 2. 현재 어떤 모델인가

| 구분 | 확인 내용 |
| --- | --- |
| 이름 / 버전 | `poisson-elo-baseline` / `0.2.0` |
| 종류 | 결정론적 통계 예측 모델. LLM 또는 언어 추론 모델이 아님 |
| 입력 | 리그별 과거 경기 결과, 득실점, 홈/원정, 경기일, 팀·시즌 |
| 팀 전력 | Poisson 공격·수비 강도 + Elo 전력 점수 |
| 결합 | 기대 득점 차이 단계에서 Poisson 60% + Elo 40%; Elo 280점을 1골 차이로 환산 |
| 시간 가중 | 일별 감쇠 0.005, 반감기 약 139일 |
| 표본 부족 처리 | 강도 prior 4경기, 승격·미관측 팀에 하위권 전력 prior |
| 출력 | 홈승·무승부·원정승 확률 및 기대 득점 |
| 확률 보정 | identity; 별도 temperature 보정 미적용 |
| 미반영 정보 | 현재 부상·명단, xG, 휴식일, 일정 강도, 시장 배당을 예측 특성으로 사용하지 않음 |

근거: [모델](../../ml/edge_ml/model.py), [강도 추정](../../ml/edge_ml/strength.py), [운영 픽](../../apps/api/edge_api/services/picks.py).

### 장점

- 구조와 입력이 명확하여 결과의 원인을 추적하기 쉽고, 같은 데이터로 같은 결과를 재현할 수 있다.
- 홈 이점·상대 팀 전력·최근 경기·승격팀을 반영한다. 기본 비율보다 낮은 확률 손실이 재현됐다.
- 추가 유료 데이터나 LLM 호출 없이 학습·평가할 수 있다. 이번 제한된 실험은 로컬 환경에서 약 13초가 걸렸다. 이는 서비스 지연시간 벤치마크가 아니다.
- 적중 여부뿐 아니라 세 결과의 확률을 제공하므로 log loss/Brier로 확신의 적절성까지 평가할 수 있다.

### 단점 및 한계

- 득점 분포와 전력의 단순화 때문에 선수 교체·전술·휴식·퇴장 등 실제 경기 조건을 충분히 표현하지 못한다.
- 혼합 모델이 Poisson 단독보다 복잡하지만, 추가 성능 이득의 신뢰구간은 0을 포함한다.
- 최근 시즌 성적이 약해졌고, 리그마다 같은 파라미터를 쓰는 것이 최선인지 확인되지 않았다.
- 사후 결과 데이터만으로는 예측 시점에 실제 수집됐던 정보와 운영 품질 조건을 완전히 복원할 수 없다.
- 배당 자료가 없어 시장보다 나은 확률인지, 수익성이 있는지 판단할 수 없다.

## 3. 이번 재평가 프로토콜

| 항목 | 설정 |
| --- | --- |
| 자료 | openfootball EPL 2018-19~2025-26, 파일별 SHA-256 저장 |
| 초기 이력 | 2018-19~2019-20 |
| 후보 선택 구간 | 2020-21~2022-23, 1,140경기 |
| 후속 비교 구간 | 2023-24~2025-26, 1,140경기 |
| 학습 | 7일마다 과거 이력으로 재학습; 최소 380경기 |
| 결과 반영 | 시작 후 3시간이 지난 경기만 학습에 허용 |
| 후보 | Poisson·Elo 출력 확률의 가중 평균; Poisson 가중치 0, 0.25, 0.5, 0.75, 1 |
| 주 지표 | log loss, 낮을수록 좋음 |
| 보조 지표 | Brier, 적중률, ECE, 시즌별 손실, 픽 제공 비율 |
| 불확실성 | 기존 경기 단위 bootstrap + ISO 주 단위 paired cluster bootstrap 4,000회, seed 고정 |

3시간은 실제 수집 타임스탬프가 없는 상태에서 둔 보수적 가정이다. 지연·중단 경기를 완전히 처리하지 못한다. 주 단위 bootstrap도 주 사이 독립성을 가정하므로 모든 시간 의존성을 제거하지 않는다.

이 시험 구간은 이전 개발에서 이미 확인됐다. **이번 결과는 사후 연구 재평가이며 완전히 미사용인 최종 시험 결과가 아니다.** 후보 가중치는 검증 구간에서만 선택했고 시험 결과로 재조정하지 않았다. 시계열 검증은 과거로 학습하고 이후 구간에서 평가하는 순서를 지켜야 한다. [공식 참고](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

## 4. 재평가 결과와 모델 교체 판단

아래는 결과 반영 3시간 지연을 적용한 동일 1,140경기 성적이다. Brier는 세 클래스 제곱오차 합의 평균이다.

| 모델 | Log loss ↓ | Brier ↓ | 적중률 ↑ | ECE ↓ |
| --- | ---: | ---: | ---: | ---: |
| 기본 비율 | 1.073656 | 0.649869 | 43.16% | 0.01418 |
| Elo 단독 | 0.986482 | 0.587869 | 52.11% | 0.02353 |
| Poisson 단독 | 0.983404 | 0.585941 | 52.54% | 0.02251 |
| 운영 v0.2.0 | **0.983187** | **0.585692** | **52.19%** | 0.02744 |
| 검증 선택 확률 앙상블 | 0.982948 | 0.585560 | 52.28% | 0.02813 |

기본 비율 대비 운영 모델의 log loss 감소는 약 8.43%다. 기본 비율 ECE가 작다고 예측력이 더 좋은 것은 아니다. 항상 비슷한 확률을 출력하는 모델은 구별 능력이 낮아도 평균 보정 오차가 작을 수 있다.

주 단위 paired CI에서 `비교 모델 − 운영`의 log loss 차이는 다음과 같다. 음수는 비교 모델이 유리함을 뜻한다.

| 비교 모델 | 평균 차이 | 95% CI | 해석 |
| --- | ---: | --- | --- |
| 기본 비율 | +0.090469 | [+0.069550, +0.111056] | 운영 모델 우위 재현 |
| Elo | +0.003295 | [−0.002666, +0.009169] | 어느 쪽 우위도 확정 어려움 |
| Poisson | +0.000217 | [−0.002472, +0.002962] | 운영의 추가 복잡도 이득 불확실 |
| 확률 앙상블 | −0.000239 | [−0.002998, +0.002407] | 개선 확정 불가 |

**앙상블 실험은 미채택이다.** 검증 구간에서 50:50이 가장 좋았지만, 운영 대비 log loss 개선은 0.000811로 미리 정한 최소 0.001에 못 미쳤다. 후속 구간에서도 개선은 0.000239에 그쳤고 CI가 0을 포함하며 ECE는 소폭 악화됐다. 검증 탈락 후보의 후속 성적은 진단용으로만 남겼다.

이번 연구 후보 기준은 검증 개선 ≥0.001, 후속 개선 ≥0.002, 주 단위 CI 상한 <0, Brier 비악화다. 통과하더라도 새로운 미사용 기간 또는 그림자 운영 검증 없이 자동 배포하지 않는다. 이 수치들은 이번 실험의 연구 기준이며 기존 운영 승격 정책을 변경한 것은 아니다.

3시간 지연 적용으로 인한 운영 log loss 차이는 +0.0000127이었다. 이번 EPL 주간 재학습에서는 영향이 작지만, 이것이 실시간 결과 가용성 문제 전체가 작다는 증거는 아니다.

## 5. 가장 중요한 QA 발견: 추천 빈도의 차이

같은 EPL 시험 경기, 같은 0.55 임계값, 같은 운영 모델을 사용했다.

| 평가 조건 | 후보 경기 | 경기 있는 날 | 픽 제공일 | 적중 | 적중률 | 픽 제공 비율 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| KST 하루 전체 | 1,140 | 396 | 233 | 166 | 71.24% | 58.84% |
| KST 09:00 시점 조건 | 446 | 396 | 97 | 68 | 70.10% | 24.49% |

09:00 조건은 이미 시작한 경기와 그때 아직 학습되지 않은 예측을 제외한다. 픽 제공일이 **136일, 약 58.4% 줄었다.** 적중률 CI는 각각 65.13~76.67%, 60.37~78.31%로 겹친다. 따라서 적중률이 유의하게 하락했다고 결론 내릴 수 없으며, 가장 명확한 차이는 추천 가능한 빈도다.

이 표는 EPL만의 결과다. 이전 10개 리그 합산 75.27%와 직접 비교하지 않는다. 분모 396은 경기가 있는 날이며 전체 달력 일수가 아니다. 09:00 결과도 배당 신선도·수집 성공·운영 팀 이력 조건이 없으므로 **시각 조건만 재현한 대리 평가**다.

새 아이디어: 오전 9시에 당일 자정까지를 보는 정책과, 오전 9시부터 다음 날 오전 9시까지를 보는 정책을 별도 실험한다. 유럽 새벽 경기가 자정 기준에서 빠지는 문제를 제품 요구와 함께 검토할 가치가 있다. 이번에는 서비스의 날짜 규칙을 바꾸지 않았다. 적중률·픽 제공 비율·평균 확률을 함께 보고 정책을 선택해야 한다.

## 6. 최근 성능 악화의 위치

| EPL 시즌 | 운영 log loss | 적중률 | 실제 무승부 수 | 무승부 경기의 평균 log loss | 전체 손실 중 무승부 기여 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2023-24 | 0.937823 | 57.63% | 82 | 1.496965 | 0.323029 |
| 2024-25 | 0.977216 | 51.84% | 93 | 1.487740 | 0.364105 |
| 2025-26 | 1.034522 | 47.11% | 104 | 1.444739 | 0.395402 |

2023-24→2025-26 전체 손실 증가 약 0.096700 중 무승부 결과군의 기여 증가가 약 0.072373, 약 74.8%다. **무승부 경기의 평균 손실은 오히려 줄었지만 무승부 비중이 늘었다.** 따라서 무승부를 더 못 맞히게 됐다는 단순 해석은 부정확하다. 이는 손실의 산술 분해이며 악화 원인의 인과적 증명은 아니다. 홈승·원정승 경기의 평균 손실도 증가했다.

개선 실험은 최근 시즌만 보고 draw 배수를 올리기보다, 과거 순차 검증에서 리그·시즌별 무승부율 변화와 득점률 변화에 반응하는 보정 후보를 비교하는 것이 타당하다. 무승부 확률을 올리면 다른 결과의 손실이 커질 수 있으므로 전체 log loss와 Brier를 함께 평가한다.

## 7. 이번에 실제로 구현한 개선

| 변경 | 목적 / 검증 |
| --- | --- |
| `backtest_daily_picks`의 선택적 decision_hour·prediction_times | 시작한 경기·선정 시각 이후 예측 제외. 09:00 경계, 늦은 예측, 무추천일 회귀 테스트 |
| 픽 제공 비율·후보 수 기록 | 적중률만으로 선택 정책을 평가하는 문제 보완 |
| 입력 길이·고유 ID·타임존 검사 | 잘못 매칭된 결과와 모호한 시각으로 평가하지 않도록 조기 오류 |
| `BacktestConfig.result_delay` | 시작한 경기 결과를 즉시 아는 것으로 처리하는 가정 완화; 기본값 0으로 기존 재현 유지 |
| `Predictions.fitted_at` | 경기별 학습 기준 시각을 보존하고 픽 평가에 전달 |
| 빈 데이터·0 이하 재학습 주기 처리 | 빈 입력 오류와 무한 루프 방지 |
| CLI의 별도 `daily_pick_timing_proxy` | 기존 전체일 평가와 오전 9시 대리 평가를 별개로 생성 |
| 오프라인 검증 스크립트 | 제한된 앙상블 탐색, 주 단위 CI, 결과군별 손실 분석, 원본 해시, 경기별 예측 저장 |

기존 `daily_pick_backtest`는 과거 결과 재현을 위해 유지하고 `legacy_whole_day_not_live_replay`로 표시했다. 기존 API는 이 메타데이터를 사용자에게 전달하지 않고 이전 평가 참조를 계속 사용할 수 있다. **실서비스에서 성적을 정확히 설명하는 수정은 아직 남은 P1 항목**이다. 새로운 대리 평가를 그대로 실운영 성적으로 교체해서도 안 된다.

| P2 | 무승부·득점률 변화 대응 | 제한된 보정 후보를 과거 구간에서 선택, 이후 시즌 전체 log loss/Brier 비악화 |
| P2 | 휴식일·일정 강도·xG 등 새 정보의 추가 가치 | 한 특성군씩 추가/제거, 결측을 포함한 동일 표본·동일 시각 비교 |
| P2 | 시장 기준선 | 예측 시각의 마진 제거 배당 확률과 비교; 종가 배당은 별도 참고 |
| P3 | 명단 발표 전/후 두 단계 모델 | 09:00 모델과 킥오프 전 모델을 분리; 실제 발표 시각 이후에만 명단 사용 |
| P3 | 그림자 평가·운영 감시 | 모델별 일별 확률/손실/픽 제공 비율/데이터 지연을 축적, 기준 위반 시 승격 보류 |

추가 아이디어는 **개선하지 못한 실험도 남기는 실험 장부**다. 이번 앙상블 미채택 결과처럼 후보·설정·데이터 해시·선택 시점·채택 사유를 기록하면 같은 시험 집합을 반복해서 최적화하는 위험을 줄일 수 있다.

LLM은 도입한다면 기사에서 부상·징계·선수 ID·공개 시각과 출처를 추출하는 보조 역할부터 시작한다. 추출의 사실 정확도와 경기 예측의 추가 가치를 따로 평가하고, LLM이 근거 없이 확률을 수정하지 않도록 한다. 현재 모델을 LLM으로 바꾸는 것 자체는 검증된 개선 방향이 아니다.
