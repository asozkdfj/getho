# Claude 전달용: 모델 정확도 개선 방향 및 QA 프롬프트

작성일: 2026-10-16 KST

## 사용자 요청과 합의한 방향

최우선 목표는 실제 미래 경기의 예측 정확도가 높은 모델이다. 현재 모델을 파악하고 장단점과 성능을 검증한 뒤, 평가 기반을 개선하고 선수·피로·이동·전술·경기 상황으로 입력을 확장한다. 변수 수를 늘리는 것 자체를 성과로 보지 않으며, 효과가 검증된 변경만 채택한다.

현재 모델은 LLM이 아니라 Poisson+Elo v0.2.0이다. 이번 QA에서 EPL 3,040경기를 읽어 기존 시험 1,140경기 결과를 재현했다. 3시간 결과 반영 지연 조건의 적중률은 52.19%, log loss는 0.983187이다. 확률 앙상블은 개선 폭과 불확실성 기준을 통과하지 못해 미채택했다.

오전 9시 조건과 하루 전체 후보 조건의 차이를 확인했다. EPL만의 동일 표본에서 픽 제공일은 233일→97일, 적중률은 71.24%→70.10%였다. 이는 배당·수집 상태까지 재현한 실운영 성적이 아니다. 이전 10개 리그 합산 75.27%와 직접 비교하지 않는다.

## 그대로 전달할 QA·개발 프롬프트

> 너의 역할은 축구 경기 예측 모델의 개발자이자 검증 담당자다. 최우선 목표는 실제 미래 경기의 홈승/무승부/원정승 예측 정확도 개선이다. 이 문서와 링크된 QA 결과를 먼저 읽고, 현재 개발 브랜치와 차이를 확인한 뒤 필요한 개선을 진행해라.
>
> 1. 현재 Poisson+Elo v0.2.0을 재현 가능한 기준 모델로 유지해 비교한다. 기존 QA의 숫자를 무조건 신뢰하지 말고 표본·시점·설정·데이터 해시를 확인한다. 현재 운영 상태와 보고서 작성 당시 상태가 다르면 차이를 기록한다.
>
> 2. 먼저 데이터 가용성 표를 작성한다. 각 변수의 공급자, 과거 커버리지, 경기 전 공개/수집 시각, 결측률, 갱신 빈도, 사용 조건·비용, 팀/선수 ID 연결 가능성을 확인한다. 외부 자료가 없으면 성능을 꾸며내지 말고 수집 요건과 구현 가능한 범위를 제시한다. 유료 서비스 구매는 별도 사용자 승인 없이 진행하지 않는다.
>
> 3. 첫 변수군은 선수 가용성·누적 출전 시간·휴식 차이·최근 경기 내용이다. 예상/확정 선발, 핵심 결장과 대체 선수 차이, 골키퍼 변경, 최근 7/14/28일 선수별 출전 시간, 연장전, 연속 선발, 양 팀 휴식 시간 차이, 과거 xG/xGA·슈팅 품질을 검토한다. 피로 계산에는 리그 외 컵·대륙대회·국가대표 경기도 포함한다. 선수 수준 자료가 없으면 팀 수준 대리 지표라고 명시한다.
>
> 4. 다음으로 이동 부담과 전술 상성을 검토한다. 이동 거리·시차·복귀 간격은 실제 이동이 아니라 추정이면 그렇게 표시한다. 포메이션은 이름 하나만 쓰지 말고 최근 사용 비율, 감독·선수 구성, 압박·수비 라인·역습·점유·세트피스 성향 등을 검토한다. 우리 압박×상대 탈압박, 높은 라인×상대 침투 같은 상호작용은 가설로 실험하며 고정된 상성 보너스를 임의로 부여하지 않는다.
>
> 5. 멘탈리티·승리 열정은 직접 측정된 사실로 취급하지 않는다. 경기 전 승점·잔여 경기·잔류/우승 경쟁·토너먼트 합산 점수·감독 교체 같은 관측 가능한 대리 지표를 우선한다. LLM이 기사나 인터뷰로 임의의 열정 점수나 승률을 생성하지 않게 한다. 뉴스 활용 시 원문 근거·공개 시각·선수 식별·상충 정보를 보존하고 추출 정확도를 별도 평가한다.
>
> 6. 오전 9시 모델과 선발 발표 후 모델을 별도 정책으로 정의한다. 오전에는 당시 알려진 예상 정보만, 발표 후에는 확정 정보를 사용한다. 사후 선발·포메이션·경기 xG·최종 순위를 과거 경기의 사전 입력에 넣지 않는다. 예상 선발/포메이션 불확실성은 가능한 시나리오를 결합하는 후보도 검토한다.
>
> 7. 기존 전체일 픽 성적을 실운영 성적으로 표시하는 문제부터 해결한다. 모델·리그·선정 시각·임계값·정책 버전이 맞는 평가만 연결하고, 전체일 과거 평가와 시각 조건 대리 평가를 명확히 구분한다. 실제 운영 재현에는 예측·배당·수집 시각과 품질 게이트가 필요하다. 09:00~당일 24:00과 09:00~다음 날 09:00 정책은 별도 비교하고 서비스 날짜 규칙을 조용히 변경하지 않는다.
>
> 8. 작은 보정 모델과 전체 특성 학습 모델을 후보로 비교하되, 변수군 하나씩 추가/제거하는 실험을 수행한다. 공통 경기 표본에서 비교하고 결측 때문에 쉬운 경기만 남는 편향을 보고한다. 알고리즘을 미리 정답으로 고정하지 않는다.
>
> 9. 시간 순서대로 학습→후보 선택→후속 평가를 분리한다. 리그·특성·임계값·파라미터는 평가 구간보다 앞선 자료로 선택한다. 이미 여러 번 확인한 2023-26 구간을 새로운 미사용 시험이라고 부르지 않는다. 새로운 외부 기간 또는 그림자 운영 자료에서 최종 확인한다. 결과 반영 3시간 지연은 실제 수집 시각의 대체 가정이라는 한계도 유지한다.
>
> 10. 사용자 목표인 전체 경기 적중률을 명시적으로 보고하고 log loss/Brier로 과신이 늘지 않는지 함께 확인한다. 추천 픽의 적중률은 추천 제공 비율·표본 수와 별도로 보고한다. 다음 실험 전에 주 지표·최소 의미 있는 개선 폭·불확실성 기준을 고정한다. 이번 QA 연구 기준은 검증 log loss 개선 ≥0.001, 후속 개선 ≥0.002, 주 단위 paired CI 상한 <0, Brier 비악화였으며 보편적인 승격 기준은 아니다. 시험 결과를 본 뒤 통과하도록 기준을 바꾸지 않는다.
>
> 11. 최근 시즌·리그·홈/무/원정·승격팀·확률 구간·결측 여부별 오차를 분석한다. 이번 QA에서 무승부 결과군의 손실 기여 증가가 발견됐지만, 무승부 조건부 평균 손실은 감소했다. 이 사실만으로 무승부 확률을 일괄 인상하지 않는다. 시장 비교는 동일 예측 시각의 배당을 확보한 경우에만 수행한다.
>
> 12. 결과물은 데이터 가용성 표, 구현 변경, 누수/경계/결측 회귀 테스트, 재현 명령, 경기별 예측과 데이터 해시, 후보별 실험 장부, 개선 전후 QA 리포트다. 미채택 실험과 실패 원인도 기록한다. 실험 성과와 운영 성과를 구분하고 검증되지 않은 후보를 자동 배포하지 않는다. Docker 없이 가능한 검증부터 진행하고 DB·운영 환경에서 미검증인 부분을 명시한다.

## 이번 Git 전달 범위

- 평가 코드: 선택 시각·예측 가용 시각 필터, 결과 반영 지연 옵션, 학습 시각 기록, 입력 검증, 추천 제공 비율.
- CLI: 기존 전체일 평가를 보존하고 별도의 `daily_pick_timing_proxy`를 생성.
- 실험: 제한된 확률 앙상블 탐색, 주 단위 paired CI, 시즌별 결과군 손실 분해, 경기별 예측 저장.
- 검증: ML 테스트 99개 통과, 변경 Python 파일 lint/format 통과, EPL 평가 CLI 실행 완료.
- 미완료: 실제 운영 품질 게이트 재현, UI/API의 평가 범위 표시 수정, 신규 변수 데이터 확보·학습, 독립 외부 기간 검증.
- 운영 모델 파라미터·버전은 변경하지 않았다. 원본 캐시와 로컬 QA 의존성은 Git에 포함하지 않는다.

첫 실행 목표는 **현재 QA 변경을 검토하고, 시점이 보장되는 데이터 수집 설계와 피로·휴식 변수군의 첫 비교 실험을 완성하는 것**이다. 나머지 변수는 가용성과 추가 예측력을 확인하며 단계적으로 확장한다.
