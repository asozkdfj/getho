# 다음 실험 준비 및 실데이터 시점 감사 — 2026-10-19 KST

담당 Codex. 기능 개발은 Claude, 독립 검증은 Codex라는 역할을 유지했다.
운영 기능 수정·모델 교체·DB 쓰기·외부 API 호출은 수행하지 않았다.

## 1. 시각 QA 선행 조건

원격 main을 다시 fetch한 결과 `d6cef46c5df38c8b0a444d4aca8e90697be4c1fb`로 이전과 동일하다.
오늘 보고한 F1~F5 수정은 main에 아직 없다. [오늘 QA](2026-10-19-independent-qa.md)의 반례가 회귀 기준이다.
따라서 운영 모델 개선을 승인하지 않고, 독립적인 읽기 전용 비교 도구부터 구현했다.

## 2. 같은 의사결정 시각의 시장 비교 — 실제 실행

`scripts/qa/audit_decision_market.py`는 PostgreSQL repeatable-read/read-only transaction에서
기존 기록을 읽는다. 비밀은 QA_DATABASE_URL 환경 변수로만 받고 출력하지 않는다.

```text
python scripts/qa/audit_decision_market.py --start 2026-10-16 --end 2026-10-20 --out .cache/2026-10-19-decision-market-final.json
python -m pytest -q scripts/qa/test_decision_market.py
```

검사 조건:

- 09:00 KST = 00:00 UTC, 다음 09:00까지의 경기. 의사결정 시각이 실행 시각보다 미래이면 제외.
- API-Football 실데이터 provider만 사용; mock 제외.
- model v0.2.0 / identity, prediction.created_at와 input_data_as_of 모두 decision_at 이하.
- 모델에 연결된 배당의 captured_at/created_at 모두 decision_at 이하.
- 같은 bookmaker의 당시 최신 저장 1X2 배당을 기준선으로 사용, 역배당 합으로 수수료 정규화.
- 예측과 배당 최대 경과 시간 72시간을 감사 규칙으로 명시. 운영 품질 게이트 전체를 대신하지 않는다.
- 이미 시작한 경기, 결측, 유효하지 않은 확률/배당, 오래된 입력은 사유와 함께 manifest에 남긴다.
- 동일 경기에서 운영·시장 단독·0.25운영+0.75시장 비교. 미래 정보로 배당을 채우지 않는다.

실행 시각 2026-10-19 00:56 KST. 조회 대상은 10/16~10/18의 의사결정 구간이며
10/19 오전 9시는 아직 미래여서 포함되지 않는다.

| 항목 | 결과 |
| --- | --- |
| 현재 일정 DB에서 조회된 경기 | 3,364 |
| 비교 조건 충족 | 943 |
| 그중 현재 결과가 확인된 경기 | 676 |
| 평가 경기 의사결정 날짜 | 10/17 506개, 10/18 170개 |

제외 사유는 중복 집계다. 예측이 없으면 같은 bookmaker도 정할 수 없어
`no_same_bookmaker_odds_available_at_decision`이 함께 기록된다. 이것을 모든 배당이 없었다는 뜻으로 해석하지 않는다.

| 동일 676경기, 서술 통계만 | Log Loss ↓ | Brier ↓ | 적중률 |
| --- | --- | --- | --- |
| 저장된 운영 모델 | 1.011212 | 0.604953 | 50.592% |
| 당시 저장된 시장 배당 | 0.985904 | 0.587177 | 53.107% |
| 25% 운영 + 75% 시장 | 0.988995 | 0.589251 | 52.959% |

시장 단독이 이 표본에서도 더 좋다. 그러나 완료 표본은 **의사결정일 2일뿐**이며,
여러 검증 전 리그도 포함한다. 리그 구성·잔여 미종료 경기·품질 필터에 따라 수치가 달라진다.
주 단위 신뢰구간이나 일반화/승격 주장을 만들지 않았다.

더 중요한 제한: 저장된 model_version.git_sha는 **`local`**이다.
운영 예측이 정확히 어느 소스 커밋에서 생성됐는지 DB만으로 추적할 수 없다.
현재 일정/결과 테이블도 과거 의사결정 당시의 후보 집합 스냅샷이 아니다.
학습 결과 관측 시각과 당시 전체 품질 게이트를 인증하지 못하므로 이 결과는 **부분 시점 감사**다.

기록:

- [요약 JSON](2026-10-19-decision-market-summary.json).
- 전체 3,364행 manifest는 로컬 `.cache/2026-10-19-decision-market-final.jsonl`에 보존.
  SHA256 `d85ba40b0d3c0df9e67c5206323329c07a37b22cdc3485b55540221012008ba3`.
- 원본 경기별 데이터는 저장소에 재게시하지 않고 재현 도구와 집계 결과를 게시했다.
- Ruff PASS, 가용 시각/잘못된 확률/빈 표본 테스트 2 PASS, 실제 DB 읽기 실행 PASS.

## 3. 선수·xG 실험 데이터 준비 상태

전체 DB 숫자는 mock을 포함하므로 실데이터만 다시 구분했다.

| 실데이터 기록 | 실제 저장량 | 해석 |
| --- | --- | --- |
| 결장 뉴스 | 239개 스냅샷, 69경기 | 조회 범위에서 아침에 양 팀 정보가 있던 경기 54개 |
| 공식 선발 | 148개 스냅샷, 74경기 | 조회 범위에서 아침에 양 팀 공식 선발이 있던 경기 0개 |
| 선수 출전 시간 | 22,762개 행, 726경기, 186팀 | 경기 기간 2026-07-31~10-18; 실제 DB 수집은 10/16 이후 |
| 과거 슈팅 기반 xG | 전용 컬럼/수집 경로 확인되지 않음 | predictions.expected_goals는 모델 출력이며 관측 xG가 아님 |

수집 당시 뉴스가 없다는 것은 부상자가 없다는 뜻이 아니다. 미수집/알 수 없음 상태를 따로 보존해야 한다.
7월 경기 출전 기록이 있어도 10월에 처음 수집한 사실을 7월 의사결정에 이미 알려진 입력처럼 쓰면 안 된다.
오전 9시의 선수 실험은 당시 결장/예상 가용성 중심이어야 하며 공식 선발은 경기 전 별도 갱신 모델로 평가한다.
API 공급자가 어떤 과거 xG를 실제 제공하는지와 라이선스/커버리지는 이번에 호출 확인하지 않았다.
현재 저장 이력만으로 선수/xG 후보를 신뢰성 있게 훈련·검증 완료했다고 주장할 수 없다.

## Claude에 넘길 구현 순서

1. 기존 시각·정산 QA 수정 및 새 SHA 회귀 검증. 예측 model_version.git_sha에 정확한 빌드 SHA 기록.
2. 09:00 후보 manifest와 제외 사유, 관측/저장/예측 시각, 모델/설정/데이터 해시를 append-only로 저장.
3. 동일 시각 baseline/시장/사전 고정 결합 후보를 비공개 병행 기록. 10/17~18 결과를 본 뒤 이 구간으로 가중치를 튜닝하지 않음.
4. 선수 기록은 historical_event_time와 observed_at을 분리. 결장 없음과 데이터 없음 구분.
   경기 전 선발 갱신은 아침 픽과 분리하고 픽 기록을 덮어쓰지 않음.
5. 관측 xG 공급 범위와 표본 확인 후 전용 수집/이력 계약 설계. 실제 확보 전 모델 입력으로 가정하지 않음.
6. 기간·최소 표본·후보 수·채택 기준을 고정한 새 평가. [개선안](2026-10-19-model-improvement-plan.md)의 기존 승격 기준 유지.

이번 완료 범위는 비교 도구 구현·테스트·실제 저장 DB 감사·선수/xG 준비도 판정이다.
운영 결함 수정과 새 데이터 수집 구현, 새 모델 학습·장기간 성능 검증은 남아 있다.
