# 베트맨 배당 기반 가상 구매·정산·구성 비교기 — 개발 명세 v0.1

- 작성: Codex, 2026-10-20 KST
- 개발 담당: Claude Code / 독립 검증: Codex
- 상태: **개발 요청 명세. 기능 구현·수익성 검증·운영 채택 완료가 아님.**
- 참고 코드 기준: main `4f45edbe5647c731601b917945963cf696db7d7a`
- 사용자 대상: 베트맨 프로토 승부식. 다른 상품은 별도 계약으로 확장한다.

## 1. 사용자 목표와 두 개발 축

1. 예측 모델의 적중률과 확률 품질을 계속 개선한다. 기존 모델 검증 기준은 유지한다.
2. 예측을 베트맨의 실제 구매 가능한 배당과 연결해, 같은 총예산에서 어떤 선택·구성이
   돈을 남길 가능성이 있는지 **가상 기록과 미관측 경기**로 검증한다.

2번이 이번 개발 범위다. 적중률 상승과 순수익 상승은 별개다. 상품명이나 화면에서
"수익 보장", "무조건 적중", "최적 수익 확정"으로 설명하지 않는다.
운영 모델 교체나 배팅 금액 확대를 전제로 개발하지 않는다.

## 2. 첫 버전 범위

### 포함

- 축구 정규시간 1X2(홈승/무승부/원정승), 베트맨에서 발매된 선택지.
- 수동 입력 또는 CSV/JSON 파일 import를 통한 회차·경기·배당 snapshot.
- 모델 예측과 베트맨 경기의 검증된 연결 및 가격 가용 시각 검사.
- 같은 예산의 단일 경기, 2경기, 3경기, 5경기 조합 비교. 단일 구매는 허용된 경기만.
- 동일 경기의 서로 다른 결과를 **별도 티켓**으로 커버한 구성의 손익 계산.
- 동결된 가상 티켓, 공식 결과 기반 정산 이력, 누적 성과와 무추천일 기록.
- 실험 조건 사전 등록과 경기별/일별 export.

### 후속 또는 제외

- 실제 구매·로그인·결제·자동 베팅은 제외한다. 이번 서비스는 가상 비교 도구다.
- 자동 수집은 별도 접근 가능성/이용 조건 검토 후 결정한다. 공식 공개 API가 있다고 가정하지 않는다.
- 핸디캡·언더오버·전반·승무패 풀 방식 상품, 라이브 배팅은 후속 명세로 분리한다.
- 손실 복구를 위한 증액, 자금 비율 최적화, Kelly 기반 배분은 v1에 넣지 않는다.
- 여러 구매처 사이의 차익거래는 베트맨 단일 구매처 MVP 범위가 아니다.
- 새 피로·선수·xG 모델 개발은 별도 축이다. 본 기능은 버전이 고정된 기존 예측으로도 작동해야 한다.

## 3. 공식 규칙과 가정의 분리

공식 참고: https://sportstoto.co.kr/faq.php (2026-10-20 확인).
프로토는 고정배당 상품이며 구매 시점 배당으로 지급액이 계산된다. 축구 일반 승부식은
정규시간 기준이고 무승부를 별도 결과로 다룬다. 실제 구매 가능 여부는 회차/경기별로 확인한다.

구현 전에 규칙 버전에 다음을 기록한다: 출처 URL, 확인 시각, 적용일, 검증 담당자.

| 규칙 | 요구 사항 |
| --- | --- |
| 단일 구매 허용/최소·최대 조합 수 | 해당 상품/경기별 확인값 사용. 모든 경기가 단일 구매 가능하다고 가정 금지 |
| 동일 대상경기의 조합 제한 | 물리적 fixture ID로 검증. 다른 시장 ID여도 같은 경기일 수 있음 |
| 마감·발매 중단·배당 변경 | 경기 시작 시각과 별도로 관리. 구매 불가능한 snapshot은 선택 제외 |
| 최소 금액·금액 단위·구매/지급 한도 | 확인된 값만 적용. 임의 상수로 공식 제약을 대체하지 않음 |
| 조합배당 절사/반올림 및 취소·무효 | 공식 정산 규칙을 검증 사례와 함께 versioning |
| 과세/공제 | 최신 공식 근거와 적용 단위까지 검증. 미확인 시 세후 값을 표시하지 않음 |

규칙 미확인 티켓은 `rules_unverified`로 분리한다. 세전 이론 계산은 가능하되
"베트맨 실제 정산 재현 완료" 또는 "세후 수익"으로 표시하지 않는다.

## 4. 데이터 계약 제안

기존 테이블과 혼합하기 전에 Claude가 migration/API 설계를 제시한다. 아래 이름은 제안이며
실제 운영 API가 이미 존재한다는 뜻이 아니다. ID와 UTC 시각은 원본 출처와 함께 보존한다.

### A. 베트맨 배당 snapshot (append-only)

- `snapshot_id`, `source=betman`, `source_mode=manual|file|approved_connector`.
- `product`, `round_id`, `event_number`, `market_type=1X2`, `selection=HOME|DRAW|AWAY`.
- 원본 팀명/리그명/국가/경기일, 연결된 `fixture_id`, `mapping_status` 및 검토 이력.
- `kickoff_at`, `sale_close_at`, `sale_status`, `single_allowed`.
- `decimal_odds`, `source_observed_at`, `stored_at`, 원본 artifact hash, `rules_version`.
- 수동으로 과거 가격을 입력하면 실제로 당시 관측한 시각을 지어내지 않는다.
  시각 증거가 없는 자료는 `historical_proxy`로 표시해 prospective 성과와 분리한다.
- 팀 이름만 같은 경기를 자동 연결하지 않는다. 국가/리그 ID·홈원정·일정까지 검증한다.

### B. 결정 snapshot

- `decision_id`, `policy_id`, `decision_at`, `prediction_id`, 모델 코드 SHA/지문/파라미터 hash.
- 입력·학습 결과의 가용 시각, 확률 벡터, 해당 배당 snapshot ID.
- `prediction_available_at <= decision_at`, 모든 입력/배당의 관측·저장 시각도 decision 이하.
- `decision_at < sale_close_at`이고 시작 전이며 발매 가능해야 한다.
- 후보 전체 manifest, 제외 사유, 데이터 부족과 정상 무추천의 구분.
- 기존 [예측 교환 계약](PREDICTION_CONTRACT_V1.md)의 시점 원칙을 유지한다.

### C. 가상 티켓/포트폴리오/정산

- 티켓: `ticket_id`, `portfolio_id`, 선택 leg 목록, 각 snapshot/prediction ID,
  가상 구매 시각, 원화 금액, 적용된 티켓 배당·규칙 버전.
- 포트폴리오: 총예산, 실제 가상 배정액, 미배정 현금, 구성 정책과 정책 버전.
- 정산: 원본 결과 ID/관측 시각, 상태 pending/won/lost/void/adjusted,
  지급액·공제·순손익·규칙 버전. 원화 및 배당 계산은 Decimal/정수 사용.
- 결과 정정은 기존 행 수정 대신 adjustment 이벤트를 추가한다. 재정산은 멱등이어야 한다.
- 정책/결정 ID 기준 유일성으로 같은 실행의 중복 티켓·중복 지출·중복 환급을 막는다.

## 5. 계산 규칙

배당 d, 보정된 확률 p일 때 단일 선택의 세전 단위 기대수익은 `p*d - 1`이다.
이는 추정 p가 타당하다는 조건부 값이며 실제 수익 보장이 아니다. 손익분기 확률 `1/d`와
모델 확률, 차이, 모델 불확실성/검증 범위를 함께 보여준다.
일률적인 확률 오차 폭을 임의로 만들지 않는다. 검증된 오차 범위가 없으면 unavailable로 표시한다.

티켓 지급액은 "공식 규칙 함수(leg 결과, 고정 배당, 금액, 공제)"로 계산한다.
포트폴리오 순손익은 모든 티켓 지급액 합계 − 총지출이다. 초기 예산과 미배정 현금도 따로 표시한다.
한 장 당첨됐다는 사실만으로 포트폴리오를 이익으로 분류하지 않는다.

### 경우의 수와 상관관계

- 5개의 서로 다른 1X2 경기라면 `3^5=243`개의 **공통 경기 결과 시나리오**를 만든다.
- 같은 경기가 여러 티켓에 들어가도 시나리오의 결과는 하나만 사용한다.
- 홈승/원정승을 나눠 산 경우 무승부 시 두 티켓 모두 질 수 있음을 명시한다.
- 같은 티켓 안의 동일 경기 중복/양립 불가능 결과는 거부한다.
- 독립 가정으로 경기 확률을 곱하면 "독립 가정 추정"으로 표시한다. 여러 티켓의
  당첨 확률을 서로 독립으로 다시 곱하지 않는다.
- 공통 시나리오에 확률을 부여해 순이익/손실 확률과 기대 손익을 계산한다.
  큰 경기 집합은 seed와 반복 수가 고정된 Monte Carlo를 사용하고 추정 오차를 기록한다.
- 경기 간 상관을 추정할 증거가 없으면 이를 숨기지 않는다. 별도 민감도 시나리오는
  가정으로 표시하고 실제 보정 확률과 혼동하지 않는다.

## 6. 공정한 구성 비교

비교할 각 정책은 같은 결정 시각·후보 경기 집합·예산을 받는다. 미래 배당으로 대체하지 않는다.
동일 금액 티켓 배정을 기본으로 하고 금액 단위로 배정되지 않은 잔액은 현금으로 남긴다.
적합한 선택이 없으면 예산을 억지로 소진하지 않는다.

초기 비교군:

1. 전액 미사용(무구매 기준선).
2. 구매 가능한 단일 경기 분산.
3. 2경기/3경기 조합.
4. 5경기 조합(사용자의 기존 방식 비교군).
5. 별도 티켓으로 일부 결과를 커버한 구성.

선택 규칙은 검증 구간에서 정한 뒤 고정한다. 전체 탐색 후보 수·선택 기준·탈락 이유를 보존한다.
순이익 확률과 기대수익은 다른 목표이므로 하나의 "최고 조합" 점수로 임의 합치지 않는다.
v1은 후보 구성의 비교표를 제공하며 자동 금액 최적화나 특정 실구매를 실행하지 않는다.

## 7. 화면 요구 사항

- 입력: 회차/결정 시각, 가상 총예산, 허용 조합 크기, 경기 중복 제약.
- 경기: 모델 확률, 베트맨 배당과 확인 시각, 손익분기 확률, 데이터 경고, 선택/관망 근거.
- 구성 비교: 총지출·미배정액, 추정 기대순손익, **전체 순이익 확률**, 손실 확률,
  최대 가능 손실, 중복 경기 노출, 당첨 티켓이 있어도 순손실인 시나리오.
- 가상 성과: 실제 정산 손익과 추정값을 분리. 세전/세후/규칙 미검증 구분.
- 실제 누적 최대낙폭은 관측 성과에서 계산. 시뮬레이션 손실 분위수와 다른 이름으로 표시.
- 해외 시장 배당은 참고 정보이며 베트맨 구매 배당 대신 수익 계산에 사용하지 않는다.
- "예측이 틀려서 실패"와 "유리한 예측이지만 배당이 낮아 손해"를 구분해 설명한다.

## 8. 성능 평가 계약

- v1은 실구매 전에 가상 기록만 축적한다. 과거 백테스트/가정 시점 평가/실시간 가상 기록을 분리한다.
- 학습·보정·정책 선택·최종 평가 구간을 시간순으로 분리한다.
- **정확한 날짜, 최소 표본, 후보 수, 평가 종료 조건, 허용 손실 기준과 승격 기준은
  후보 성과를 확인하기 전에 별도 등록한다.** 이 문서의 구현 완료와 수익성 통과는 별개다.
- 기존 2023~26 모델 후속 구간과 이미 본 676경기는 탐색 자료이며 새 최종 평가로 재사용하지 않는다.
- 보고: 순손익, ROI(총순손익/총지출), 순이익일 비율, 적중률, 지출·추천 빈도,
  연속 손실, 최대낙폭, 리그별/배당 구간별 성과. 지출 0이면 ROI는 null이다.
- 적중률 분모는 실제 정산된 유효 티켓으로 명시. pending/void/무추천/실패 실행은 각각 별도 집계한다.
- 정책 차이는 동일 기간 paired 비교. 주 단위 cluster bootstrap에서 같은 경기와
  해당 경기에 연결된 티켓의 의존성을 보존한다. 여러 주에 걸친 연결 티켓의 처리도 사전 고정한다.
- 표본이 부족하거나 신뢰구간이 넓으면 INCONCLUSIVE. 손실 결과를 보고 평가 기간을 바꾸지 않는다.
- 실제 구매 가능한 배당으로 검증하지 못하면 베트맨 수익성 검증 PASS를 주지 않는다.
- 모델 확률 품질은 별도로 Log Loss/Brier/calibration을 유지한다. 고배당 몇 번의 적중만으로 채택하지 않는다.

첫 PR은 **A만 구현**한다. C부터 화면에 "추천"을 먼저 붙이거나 E의 성과를 미리 주장하지 않는다.
각 PR에 base/head SHA, migration, 테스트 명령, 실제/fake 데이터 여부, 제약을 적는다.
기존 운영 픽과 분리된 연구 기능으로 만들고 기존 예측·픽 기록을 덮어쓰지 않는다.

## 10. 필수 QA 반례

- [ ] 동일 팀/리그 이름, 홈원정 뒤집힘, 일정 변경, 다른 회차의 경기 번호 충돌.
- [ ] 관측은 결정 전이나 저장은 결정 후인 배당, 마감 이후 입력, 판매 중단, 가격 갱신.
- [ ] 단일 불가 경기, 불법 조합 구조, 같은 fixture 다른 market 중복, 원화 단위/한도 위반.
- [ ] NaN/음수/합계 불일치 확률, 배당 누락, 모델 버전 또는 예측 ID 변경.
- [ ] 한 티켓이 적중했지만 총수입이 총지출보다 작은 구성 → 순손실.
- [ ] 홈/원정 양쪽 구매 후 무승부 → 둘 다 패배(일반 1X2).
- [ ] 같은 경기 포함 티켓들이 함께 실패 → 티켓 간 독립 계산 금지.
- [ ] 무효/취소/결과 정정, 정산 재실행·동시 실행 → 중복 지급 없음.
- [ ] 공식 절사·반올림·공제 적용 전후 경계. 규칙 미확인 시 세후 값 차단.
- [ ] 무추천일/수집 실패일/정산 대기일이 성과 기록에서 사라지지 않음.
- [ ] 전체 예산 동일, 미배정 현금 보존, 조합 수 증가로 총지출이 몰래 늘지 않음.
- [ ] 추정상 유리한 확률을 입력해도 실제 수익 보장 문구나 자동 구매가 나오지 않음.

## 11. 기존 QA와의 의존성

현재 알려진 CQ-1(리그 ID), STAT-1(부분 통계), SHOT-1(결과 시점) 해결 전에는 관련
데이터의 준비도/새 후보 성능을 신뢰했다고 표시하지 않는다.
다만 A/B의 계약·합성 정산 테스트 개발은 병행 가능하다.
참고: [밤사이 QA](2026-10-20-overnight-review.md),
[이전 개발 준비 검토](2026-10-19-next-stage-readiness.md).

**Claude 인계:** 본 문서를 기준으로 A 단계의 schema와 import/mapping PR부터 제출한다.
공식 규칙 중 확인하지 못한 항목은 가정으로 채우지 말고 미확인 목록으로 명시한다.
Codex는 코드/실행 결과를 검증하며 모델 교체·main merge·운영 배포는 직접 수행하지 않는다.
