## 목적과 기존 기능의 차이

사용자가 선택한 경기와 픽을 알려주면 선택 당시 알 수 있던 리스크를 설명하고,
경기 후 실제 결과 및 사건을 대조해 다음 판단을 개선할 기록을 만든다.
기존 /review는 날짜별 모델 최우선 예측·시장·결과 비교다.
사용자 선택과 모델 최우선 선택은 별개로 저장한다. 기존 모델 성과 분모에 사용자 픽을 섞지 않는다.

기존 베트맨 명세 A~E와 연결한다. A의 배당/경기 연결을 재사용하고,
B의 티켓·정산 모델과 중복 테이블을 만들지 않는다.
실제 구매 기록은 사용자가 입력한 기록일 뿐 서비스의 결제/실구매 실행 기능이 아니다.

## 사용자 흐름

1. '내 픽 기록'에서 날짜·리그·팀으로 경기 검색 후 홈승/무승부/원정승 선택.
2. 개별 픽인지 조합인지 구분. 당시 배당·선택 시각·선택 이유 입력.
   금액과 사용자 예상 확률은 선택 사항. 금액 없어도 경기 리스크 분석 가능.
3. 원본 경기와 홈/원정·시각을 확인하고 저장. 모호한 경기 연결은 확정 전 분석 보류.
4. 경기 전이면 '당시 리스크', 경기 후이면 '당시 판단과 실제 결과'를 표시.
5. 월/기간별 개인 복기에서 반복되는 패턴과 데이터 부족을 확인.

MVP는 구조화된 직접 입력/CSV와 기존 경기 검색이다.
자연어/티켓 이미지 입력은 후속 단계로 둔다. 추가할 때 추출한 경기·선택·배당을
사용자가 확인하기 전 확정하지 않는다. 이미지 원본은 기본 비공개, 계정/식별정보는 최소 보존.
지원 상품은 축구 정규시간 1X2. 다른 시장을 승무패로 억지 변환하지 않는다.

## 필수 데이터 계약

이름은 제안이며 migration/API 계약은 Claude가 구현 PR에서 확정한다.

- selection_id, ticket_id(선택), fixture_id, Betman event/mapping revision ID.
- user_selection, market_type, decision_at, recorded_at, time_evidence.
- source_type: prospective_record / retrospective_self_report / paper.
  실제 구매 여부는 별도의 self_reported_purchase 플래그이며 검증된 구매로 표시하지 않는다.
- user_reason(선택), user_probability(선택), entry_odds(선택), stake_krw(선택).
- odds_snapshot_id, prediction_id, probability vector, model/code/input/rule version.
- 각 입력 observed_at/available_at, mapping 결정 시각, 근거 출처 및 해시.
- analysis_version, analysis_created_at, 분석에 사용한 증거 ID와 제외/부족 사유.
- settlement/result observation ID, settled_at, adjustment 이력.

선택 시각과 서버 저장 시각을 분리한다. 경기 후 입력한 과거 선택은
retrospective_self_report로 표시한다. 실제 사전 기록과 합쳐 검증 성과를 만들지 않는다.
과거 시점 예측이 없으면 unknown. 최신 모델로 재생한 값은 별도 research_replay로 구분.
본인 확률이 비어 있으면 모델 확률을 사용자 확신으로 대체하지 않는다.

저장된 선택/분석은 버전으로 보존한다. 수정은 새 revision, 중복 제출은 idempotency key.
경기 전 기존 선택을 변경하면 시각별 이력을 남긴다. 결과를 본 뒤 수정한 픽이
사전 적중률로 소급되지 않도록 한다. 결과 정정도 기존 정산 덮어쓰기 대신 adjustment.
사용자는 기록 삭제/내보내기가 가능해야 하며 삭제로 사라진 기록은 성과 집계의 완전성에 표시한다.

## 사전 리스크 분석

항상 사용자 선택 결과의 확률을 보여준다. 모델 최우선 결과와 다르면 두 결과를 나란히 표시.
다음 근거를 구분해 제시한다.

| 항목 | 계산/표시 | 자료 부족 시 |
| --- | --- | --- |
| 선택 자체의 실패 가능성 | 1 - 선택 결과의 모델 확률, 무승부/반대편 확률 분리 | 예측 없음 |
| 당시 시장과 의견 차이 | 동일 시각 시장의 같은 결과 확률과 비교 | 시각 불일치/시장 없음 |
| 배당과 손익분기 | 실제 입력 배당 d에 1/d; p*d-1은 모델 가정의 추정치 | 배당 없음, 수익 판단 불가 |
| 선수/일정 정보 | 당시 저장된 결장·출전 불투명·일정 정보만 근거로 표시 | 미수집을 정상으로 간주 금지 |
| 정보 품질 | 배당 경과시간, 모델 버전, 리그 검증 범위, 결측 | 명시적 경고 |
| 조합 구조 | 각 경기 실패 위험, 공유 경기 노출, 중복/같은 경기 상충 선택 | 상관 자료 부족 표시 |

시장과 다르다는 이유만으로 오답/좋은 가치로 판정하지 않는다.
최근 연구의 '10%p 초과 과신'은 전체 탐색 결과이지 개별 픽 배제 규칙이 아니다.
검증되지 않은 종합 위험 점수(예: 87/100)는 만들지 않는다.
보여주는 위험에는 계산식·근거·관측 시각이 있어야 한다.

조합 성공 확률 곱은 독립 가정의 추정으로만 표시한다.
같은 fixture가 포함된 여러 티켓은 공통 경기 결과를 공유해야 한다.
금액/공식 정산 규칙이 없으면 순손익을 만들지 않고,
미확인 규칙은 rules_unverified, 세후 수익은 계산하지 않는다.
베트맨 B/C 단계에서 계산기를 공용화한다.

## 경기 후 복기: 세 층으로 분리

1. **당시 확인 가능한 위험:** 결정 시점까지 알려진 정보만 다시 보여준다.
2. **경기 중 관측된 사건:** 퇴장·부상·득점 시각·슈팅/xG 등 제공자가 실제 제공한 자료.
   사건 발생 시각과 시스템 관측 시각을 모두 보존한다.
3. **해석과 불확실성:** 어떤 위험이 실제 결과와 함께 나타났는지 설명한다.
   단일 경기로 '패배 원인 확정', '멘탈 부족', '전술 때문에 졌다'고 단정하지 않는다.

예: '당시 무승부 확률 25%였고 실제로 무승부가 발생했다'는 설명은 가능하다.
'무승부를 골랐어야 했다'는 결과에 맞춘 결론은 내리지 않는다.
퇴장 후 패배는 관측 사실일 수 있어도 퇴장이 없었으면 이겼다는 반사실은 미검증이다.

정답/오답과 판단 품질을 별도 필드로 둔다.
적중해도 데이터 부족·가격 불일치가 있었을 수 있고, 실패해도 알려진 위험 범위일 수 있다.
하나의 실패를 곧 모델 결함이라고 부르지 않는다.
모델 확률의 적절성은 누적 같은 조건 표본의 적중 빈도/LL/Brier로 평가한다.

## 화면과 API 제안

개인 기록은 기존 /review와 구분한 '내 픽 복기' 탭으로 제공한다.
상단에는 내 선택·모델 선택·기록 유형·결과, 본문에는 당시 위험·경기 중 사실·다음 확인사항.
완료되지 않은 경기는 경기 전 정보만 표시하고 사후 설명을 생성하지 않는다.
정보가 없으면 빈 분석을 그럴듯한 문장으로 채우지 않는다.

API 제안: POST /personal-picks, GET /personal-picks/{id},
POST /personal-picks/{id}/revisions, GET /personal-picks/{id}/review,
GET /personal-picks/summary. 경로는 기존 라우팅과 충돌 여부 확인 후 확정.
기록/리비전/정산은 트랜잭션으로 처리한다. 페이지는 각 섹션 실패를 분리 표시.
사용자 기록은 기존 비공개 접속 경계를 유지한다. 여러 사용자 지원 시 소유권 검증을 선행한다.
노트/입력 문자열은 이스케이프하고 로그에 티켓 이미지·개인정보를 남기지 않는다.

LLM은 MVP 필수가 아니다. 먼저 검증 가능한 수치와 문장 템플릿으로 구현한다.
후속 LLM 설명은 구조화된 증거를 읽어 요약만 하며 확률/정산/리스크 판정을 생성하지 않는다.
사용자 메모와 외부 기사 속 지시문은 데이터로 취급하고, 근거 없는 설명은 보류한다.

## 개인 학습과 모델 개선 연결

개인 선택 집합은 선택 편향이 있으므로 전체 모델 검증 표본으로 쓰지 않는다.
경기 적중률·티켓 적중률·정산 수익률·제공률을 분리하고
미정산/무효/사후 입력/누락 가격/삭제 기록의 수를 함께 보고한다.
같은 경기를 여러 티켓에 넣어도 모델 평가의 경기 표본은 한 번만 센다.
사용자 이유와 결과에서 오류 가설을 모으되, 매 실패마다 모델 가중치를 자동 변경하지 않는다.
새 가설은 독립 기간의 사전 등록 실험으로 전달한다.

## 구현 순서

- R0: 현재 BETMAN-TIME-1(as-of 매핑) 수정과 회귀 통과.
- R1: 사용자 선택 저장/리비전/경기 연결/기록 유형/당시 예측 동결 + 사전 리스크 화면.
- R2: 결과 이력·정산과 연동한 사후 복기. 사실/당시 위험/해석 분리.
- R3: 조합 공통 결과 기반 분석과 누적 개인 통계. 베트맨 B/C와 공용 구현.
- R4: 증거가 확보된 범위에서 사건 요약·자연어 입력 확장.

첫 PR은 R0 또는 이미 수정됐다면 수정 SHA 검증 후 R1로 제한한다.
본 명세는 기능 구현 승인 요청을 다시 요구하지 않는다. 개발 작업은 Claude,
독립 QA와 성능 개선 검토는 Codex가 맡는다.

## 필수 QA와 수용 기준

1. 사용자가 원정승 선택, 모델 홈승 우세인 사례에서 원정승 확률로 분석한다.
2. 늦은 매핑/예측/배당/선발/결과 정정이 동결된 사전 분석을 바꾸지 않는다.
3. 경기 후 입력한 적중 픽은 prospective 성과에 들어가지 않는다.
4. 예측/배당/금액/사건 누락을 0 또는 정상으로 채우지 않는다.
5. 같은 이름의 팀, 다른 리그/날짜, 홈원정 반전은 자동 연결을 확정하지 않는다.
6. 동일 요청 재시도·동시 저장·결과 재수신에서 픽/지출/환급 중복이 없다.
7. 조합 일부만 적중, 무승부 양쪽 실패, 공통 경기 공유, 취소/정정 사례를 정산한다.
8. 적중한 낮은 확률 픽과 실패한 높은 확률 픽에 결과만으로 판단 품질을 붙이지 않는다.
9. 개인 픽과 모델 전체 성과, 사전 기록과 사후 자기보고의 분모가 분리된다.
10. 시간대(KST/UTC), 마감, 경기 시작, 무효/연기, 빈 목록/부분 API 오류가 처리된다.
11. 미래 사건이 사전 설명에 새어 나오지 않고 모든 사실 설명이 증거 ID로 추적된다.
12. 권한 없는 기록 조회/수정과 노트 HTML 삽입을 거부한다.

검토 판정: 범위를 위처럼 나누면 개발 가능. 현재 코드에 이 기능이 완성됐다는 뜻은 아니다.
R0의 알려진 시점 결함 해결 전에는 신뢰할 수 있는 과거 복기 완료로 표시하지 않는다.
