# 실데이터 연결 인계

2026-10-16: 사용자 요청으로 연결 준비. 아직 API 키가 없어 실제 공급자 요청·실데이터 seed·실데이터 테스트는 실행하지 않았다. 현재 데모 스택은 유지한다.

## 필요한 입력

- 현재 checkout의 Git 제외 파일 `.env`에 `API_FOOTBALL_KEY`를 입력한다. 키를 채팅·로그·Git에 기록하지 않는다.
- Mac의 코드 커밋/브랜치, 리그 범위, 북메이커, 수집 주기와 데이터 공급자 설정을 확인한다.
- 같은 코드·설정은 재현할 수 있지만 Mac의 로컬 DB 이력은 자동 이동되지 않는다. 과거 배당·픽 이력까지 일치시켜야 하면 별도 DB 백업/복원 계획이 필요하다. 기존 DB를 무단 덮어쓰지 않는다.

## 연결 순서

1. 키 입력 후 `scripts/local/stack.ps1 check-provider` 실행. Compose `run --no-deps --entrypoint python`으로 기존 API entrypoint의 migration/seed를 우회한다. DB 쓰기는 하지 않지만 공급자 API 요청량은 사용한다.
2. 플랜 활성 상태, 조회 가능한 리그·시즌, 배당 유무, 남은 요청량 확인. 구매·플랜 변경은 별도 요청 없이 수행하지 않는다.
3. Mac 설정과 요청 예산을 확인한 뒤 `.env`의 DATA_PROVIDER를 api_football로 전환한다. 최초 연결 때 기본 all/40개 리그 backfill을 무조건 실행하지 않는다. 검증 범위와 수집량을 먼저 정한다.
4. 데모와 실데이터는 provider로 분리된다. 먼저 제한된 수집과 예측을 확인한 후 worker 주기 수집을 시작한다. 여러 PC가 같은 API 키를 사용하면 요청량이 합산될 수 있다.
5. 실데이터 테스트: 상태/최근 수집 성공, provider 표시, 실제 경기 ID와 시간, 배당 시각, 예측 확률 합, 상세 화면, 픽 품질 조건, 모델 성과의 provider 분리를 검증한다.

기존 `tests/smoke/smoke.sh`는 `is_demo=True`, 여러 리그, 예측 경기 2개 등을 요구하는 **mock 전용 스모크 테스트**다. 실데이터에서 그대로 통과한다고 주장하지 않는다. 실제 일정·배당 결측·표본 부족은 연결 실패와 구분해야 한다.

## Mac과 비교할 환경

- 같은 Git 커밋, package-lock.json, uv.lock, 모델 버전/파라미터
- 같은 provider·리그·북메이커·시간대·선정 시각·수집 주기
- 같은 데이터 스냅샷/수집 기준 시각(정확한 수치 비교 시)
- Python 3.12, Node 22, PostgreSQL 16, Redis 7의 컨테이너 구성
- CPU 아키텍처 및 이미지 digest 차이는 기록한다. Mac arm64와 Windows amd64는 동일 바이너리가 아니다.

실데이터 연결이 끝나면 이 문서와 담당 작업 기록에 실제 실행 명령·결과·남은 차이를 추가한다.
