# 선수 가용성 실험 (초안, 아직 사전 등록 아님)

**상태:** 초안입니다. 데이터 준비 상태(`edge availability-readiness`)를 서버에서 확인한 뒤, **어떤 결과도 보기 전에**
빈칸(쓸 리그, 시즌 분할, 최소 표본)을 채워 다시 커밋해야 사전 등록이 됩니다. 그 전에는 실험 코드를 실행하지 않습니다.

## 왜 하나

Codex의 QA 후 모델 방향 검토(2026-10-21)는 다음 새 정보 후보로 선수 가용성을 꼽았습니다. 동시에 "효과를 입증한 것은 아니다.
수집량·누락·관측 시각 확인이 먼저다"라고 했습니다. 선발 명단 강도는 2단계 실험(ADR-014, StatsBomb 2015/16 4개 리그)에서
채택 가능 조건은 만족했지만 효과가 작고 CI가 0을 포함했습니다. 기각된 변수가 아니라 표본이 부족했던 변수입니다.
API-Football 과거 출전 기록(`edge backfill-appearances`)으로 훨씬 큰 표본을 만들 수 있습니다.

## 두 갈래로 나눕니다

| 갈래 | 언제 아는 정보 | 과거 재현 | 평가 방식 |
| --- | --- | --- | --- |
| **L. 선발 발표 후** | 공식 선발 11명(킥오프 약 1시간 전) | 가능: 과거 경기의 선발·출전 시간은 실제로 그 시각에 알려진 사실 | 과거 경기 walk-forward, 한 번 채점 |
| **M. 아침(09:00) 결장 정보** | 결장·출전 불투명 보고(경기 1~2일 전부터) | 불가: 과거 결장 목록에는 언제 알려졌는지가 없음 | 미래 경기만, 수집 시각이 있는 기록으로 |

- 오늘의 픽은 09:00에 고정되고 선발 명단을 쓰지 않습니다(ADR-026). L이 통과해도 아침 픽은 바뀌지 않습니다.
  L은 "선발 발표 후 갱신 분석"이라는 별도 제품의 근거가 됩니다. 아침 예측을 덮어쓰지 않습니다.
- M만 아침 픽에 영향을 줄 수 있습니다. 결장 정보는 서비스가 수집 시각과 함께 모은 기록(2026-10~)만 씁니다.

## 지금 고정하는 것 (L)

- **후보:** ADR-014 공식 그대로입니다. 새 공식을 만들거나 계수를 더 탐색하지 않습니다.
  - 선수 가중치 = 팀의 최근 10경기(`RECENT_MATCHES`)에서 뛴 시간 비중
  - XI 강도 = 오늘 선발 11명의 가중치 합 ÷ 평소 XI(가중치 상위 11명) 합. 상한 1.0, 이전 경기 3경기 미만이면 1.0
  - `log λ' = log λ + β(S_자기−1) − γ(S_상대−1)`. β, γ는 검증 구간에서만 Poisson 최대우도로 맞추고 고정
- **비교 대상:** 같은 경기의 운영 모델(v0.2.0). 판단은 운영 모델 대비로만 합니다.
- **참고만 하는 것:** 슈팅 후보(shadow-v2 후보)와 함께 쓴 결과, 리그별 결과. 판단에 쓰지 않습니다.
- **운영 모델 학습 범위 수정:** 기존 `backtest-lineups --source db`는 선발 기록이 있는 경기만으로 운영 모델을 학습했습니다.
  실험에서는 운영 모델이 끝난 경기 전체로 학습하고, 선발 기록이 있는 경기만 채점합니다(운영 모델을 일부러 약하게 만들지 않기 위해).
- **판단 기준(ADR-011과 shadow-v2와 같은 수준):** 후속 구간에서
  1. log loss 개선 ≥ 0.002
  2. 주 단위 paired bootstrap 95% CI 상한 < 0
  3. Brier 악화 없음
  4. **적중률이 떨어지지 않음 (사용자 결정, 2026-10-22):** 같은 경기에서 최다 확률 결과를 맞힌 비율의 차이
     (후보 − 운영)를 주 단위 paired bootstrap으로 구한 95% CI 하한이 **−1.0%p보다 커야** 합니다.
     확률 품질이 좋아져도 맞힌 비율이 1%p 넘게 떨어질 수 있으면 탈락입니다.
  - 네 가지를 모두 만족해야 통과입니다.
  - 검증 구간은 β, γ를 맞추는 데만 씁니다. 검증 구간 성적으로 후보를 고르지 않습니다.
- **함께 보고(판단에는 쓰지 않음):** 고친 오답·새로 틀린 정답·바꿨지만 둘 다 틀린 경기 수
  (Codex 권고: 확률 품질과 적중률을 구분).

## readiness 확인 뒤, 채점 전에 채울 것

| 항목 | 정하는 방법 |
| --- | --- |
| 쓸 리그 | `strength_ready` 경기가 충분한 검증 리그. 리그를 고르는 기준은 경기 수만 보고 정합니다(결과는 보지 않음) |
| 시즌 분할 | 검증 = 앞 시즌(들), 후속 = 마지막 완료 시즌. 선수 기록이 있는 시즌 수를 보고 정합니다 |
| 최소 표본 | 후속 구간 경기 수의 하한. 미만이면 "판단 불가" |

적중률 기준(위 4번)은 2026-10-22 사용자가 정했습니다. 어떤 실험 결과도 나오기 전입니다.

## M (아침 결장 정보)는 지금 사전 등록하지 않습니다

결장 정보가 어떤 리그에서 얼마나 일찍, 얼마나 빠짐없이 들어오는지(`morning_live`)를 먼저 봐야 정의를 정할 수 있습니다.
L의 결과와 결장 수집 현황을 본 뒤 별도 프로토콜(shadow-v3 형태, 미래 경기)로 등록합니다.

## 하지 않는 것

- 이미 미채택된 피로·휴식, 순위·동기, 무승부 보정, 확률 앙상블을 이 실험에 섞지 않습니다.
- 결과를 본 뒤 공식·계수 범위·분할·리그를 바꾸지 않습니다. 바꿔야 하면 새 프로토콜로 다시 등록합니다.
- 통과해도 자동 반영은 없습니다. Codex 독립 QA와 사용자 승인이 먼저입니다.
