# 관측 xG·슈팅 데이터 출처 조사 (2026-10-19)

Codex 준비도 감사(권장 순서 5번): "관측 xG 공급 범위와 표본을 확인한 뒤 전용 수집·이력 계약을 설계한다. 실제로 확보하기
전에는 모델 입력으로 가정하지 않는다." 이번 작업은 **조사와 확인 도구까지**입니다. 모델·수집·DB는 바꾸지 않았습니다.

여기서 xG는 **경기가 끝난 뒤 슈팅 상황으로 계산한 기대 득점**입니다. 우리 모델이 출력하는 예상 득점
(`predictions.expected_goals_*`)과 다릅니다. 예측할 경기 자체의 xG는 그 경기 전에는 존재하지 않으므로, 입력이 될 수
있는 것은 **과거 경기의 xG**뿐입니다.

## 출처별 확인 결과

| 출처 | 이 환경에서 접속 | 내용 | 범위 | 이용 조건 | 판단 |
| --- | --- | --- | --- | --- | --- |
| 보유 CSV (Club Football Match Data) | 이미 보유 | 팀별 **슈팅·유효 슈팅** 수(xG 없음) | 우리 9개 리그 2019-20~2026-27 **100%**(약 2.3만 경기). 파일 전체 38개 디비전 중 21개가 90% 이상 | 기존 실험에서 사용 중 | **슈팅 기반 대리 변수**로 바로 실험 가능. xG라고 부르지 않음 |
| API-Football `/fixtures?ids=` statistics | 키가 없어 실호출 불가 | 팀별 `Total Shots`, `Shots on Goal`, `expected_goals` | 리그·시즌별로 다를 수 있음(**미확인**) | 사용자 구독 범위 | **`edge check-xg`로 확인 필요**. 이미 결장·출전 기록에 쓰는 요청과 같은 응답 |

"차단(000)"은 이 클라우드 환경의 네트워크 정책 때문에 연결되지 않았다는 뜻입니다. 그 서비스가 없다는 뜻이 아닙니다.

## 확인 도구: `edge check-xg`

```bash
uv run edge check-xg --days 7 --limit 40   # .env에 실제 API-Football 키가 있을 때
```

- 최근 끝난 경기를 리그별로 골고루 골라 상세(`/fixtures?ids=`, 요청당 20경기)를 받습니다. 그리고 리그마다 통계가 온
  경기 수, 양 팀 xG가 모두 온 경기 수, 예시 값을 보여 줍니다.
- 요청 수는 약 1 + 일수 + limit/20입니다(기본값이면 약 11회). DB에는 아무것도 쓰지 않습니다.
- 가짜 응답으로만 테스트했습니다. **실제 응답에서 `expected_goals` 필드 이름과 값 형식은 아직 확인하지 않았습니다.**
  이 명령을 실행해 보면 확인됩니다.

## 다음 단계 제안 (결정 필요)

1. **API-Football xG 범위 확인(사용자 실행, 요청 약 11회):** `edge check-xg` 결과로 검증 리그에 xG가 오는지 봅니다.
2. **xG가 온다면 수집 계약부터 만듭니다.** 이번에는 만들지 않았습니다.
   - 표 `match_statistics`(append-only): fixture, team, provider, shots, shots_on_target, expected_goals, `observed_at`
     (= 저장 시각), source(`ingest` / `backfill`).
   - 끝난 경기 상세를 받을 때 함께 저장합니다(추가 요청 없음). 지난 시즌을 백필하면 `backfill`로 표시하고, 당시에
     알던 정보로 쓰지 않습니다(ADR-025와 같은 원칙).
   - 결정 시점 읽기는 `observed_at ≤ 결정 시각`만 씁니다.
3. **슈팅 기반 대리 변수 실험(지금 가능):** 보유 CSV의 슈팅·유효 슈팅으로 팀 공격·수비 강도를 추정해, 결과(득점) 기반
   전력에 더하는 후보입니다.
   - 기존 피로·순위 실험처럼 **실행 전에 사전 등록**합니다(학습·검증·후속 구간, 기준 = 검증 ≥ 0.001, 후속 ≥ 0.002,
     CI 상한 < 0, 시장 대비 비교 포함).
   - 한계: CSV에는 관측 시각이 없어, 결과와 같은 "킥오프 3시간 뒤 사용 가능" 가정을 씁니다. 그래서 운영 시점 검증이
     아니라 대리 평가입니다.
4. **StatsBomb**은 xG 값의 대략적인 검증 외에는 쓰지 않습니다. 쓰면 출처를 표기합니다.

어떤 경우에도 확보하고 시점을 확인하기 전에는 xG를 모델 입력으로 가정하지 않습니다. 운영 모델 교체는 사전 등록 평가,
Codex QA, 사용자 승인을 거칩니다.

## 실행 결과 (2026-10-19, 사용자 실행)

`edge check-xg --days 7 --limit 40`, 검증 리그 10개로 제한(`API_FOOTBALL_LEAGUES=39,40,78,79,140,135,61,88,94,218`):

| 항목 | 결과 |
| --- | --- |
| 확인한 경기 / 리그 | 40경기 / 10개 리그 |
| xG가 온 리그 | **10/10** |
| 양 팀 xG가 모두 온 경기 | **40/40**(포르투갈은 그 기간 1경기) |
| 값 예시 | 0.40 ~ 3.49 |
| 사용한 요청 | 11 |

최근 경기에서는 검증 리그 모두 `expected_goals`가 옵니다. 지난 시즌 경기에도 있는지는 `--now`를 과거 날짜로 주고
따로 확인합니다. 수집은 ADR-029로 시작했습니다.
