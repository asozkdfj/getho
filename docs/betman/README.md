# 베트맨 배당 가상 비교기 — A단계 (입력·경기 연결·규칙 목록)

Codex 개발 명세 [v0.1](../qa/2026-10-20-betman-profit-simulator-development-spec.md)의 **A단계**입니다.

**실제 구매는 하지 않습니다.** 로그인, 결제, 자동 구매도 없습니다. 이 기능은 연구용 입력 장치이며, 수익이나 적중을 보장하지 않습니다.

## 지금 되는 것과 아직 안 되는 것

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| **A** | 베트맨 배당 입력(CSV/JSON), 경기 연결, 구매 가능 여부 검사, 공식 규칙 목록 | **이번 구현** |
| B | 가상 티켓·정산 기록 | 다음 |
| C | 같은 예산의 구성 비교(단일, 2·3·5경기 조합, 결과 나눠 사기) | 이후 |
| D | 연구 화면과 내보내기 | 이후 |
| E | 사전 등록한 미래 경기 가상 기록 | 이후 |

A단계는 **추천을 하지 않습니다.** 모델 확률과 배당을 묶어 "사라"고 말하는 기능은 C단계 이후이며, 그것도 가상 비교입니다.

## 1. 배당 넣기

베트맨 화면의 프로토 승부식 축구 1X2 배당을 파일로 옮겨 넣습니다. 형식은 [`example-round.csv`](example-round.csv)를 보세요.
이 예시 파일의 값은 **형식 설명용 가짜 값**입니다.

| 열 | 필수 | 설명 |
| --- | --- | --- |
| `product` | ✅ | 상품 이름. 예: `proto` |
| `round_id` | ✅ | 회차. 예: `2026-81` |
| `event_number` | ✅ | 회차 안의 경기 번호 |
| `league`, `home`, `away` | ✅ | 베트맨에 보이는 이름 그대로(한글 약칭 그대로 넣으면 됨) |
| `country` | | 베트맨에 보이는 국가 |
| `kickoff_at` | ✅ | 경기 시작. `2026-10-24T21:00+09:00`처럼 시간대를 붙임 |
| `sale_close_at` | | 발매 마감. 없으면 그 배당은 "구매 가능"으로 세지 않음 |
| `sale_status` | | `on_sale`, `suspended`, `closed`, `unknown`(기본) |
| `single_allowed` | | 단일 구매 가능 여부 `true`/`false`. 모르면 비움 |
| `odds_home`, `odds_draw`, `odds_away` | 하나 이상 | 소수 둘째 자리까지 |
| `observed_at` | | 베트맨에서 그 배당을 **실제로 본 시각** |

**서버에서 실행:** 맥북에서 파일을 보내지 않아도 표준 입력으로 넣을 수 있습니다.
```bash
cd ~/getho
infra/server/edge.sh betman-import --file - --format csv --assume-tz Asia/Seoul --observed-now < round.csv
```
- `--assume-tz Asia/Seoul`: 시간대를 안 붙인 시각을 한국 시간으로 읽습니다.
- `--observed-now`: "지금 베트맨 화면을 보고 옮겼다"는 뜻입니다. 넣는 시각을 관측 시각으로 기록합니다.
- 둘 다 없으면 관측 시각이 없는 **과거 대용 자료(`historical_proxy`)** 로 저장됩니다. 대용 자료는 구매 가능한 가격으로 세지 않고, 미래 경기 성과와도 섞지 않습니다.
- 지난 배당을 나중에 옮겨 적을 때는 `--observed-now`를 쓰지 마세요. 관측 시각을 지어내면 안 됩니다.

**검사:**
- 파일의 한 줄이라도 잘못되면 **아무것도 저장하지 않고** 모든 오류를 보여 줍니다. 예: 배당이 1 이하이거나 숫자가 아님, 소수 셋째 자리, 시간대 없음, 마감이 시작보다 늦음, 관측 시각이 미래, 같은 경기 번호 중복, 홈팀과 원정팀이 같음.
- 같은 파일을 다시 넣으면 아무것도 바뀌지 않습니다.
- 배당이 바뀌어 새로 넣으면 새 기록으로 쌓입니다. 이전 기록은 지우거나 고치지 않습니다.

## 2. 경기 연결

베트맨 경기를 우리 경기(fixture)에 연결해야 모델 예측과 비교할 수 있습니다.

**자동 연결 조건:** 아래가 모두 맞을 때만 자동으로 연결합니다. **이름이 같다는 이유만으로는 연결하지 않습니다.**
1. 리그 이름을 사람이 확인해 등록함(별칭)
2. 홈·원정 팀 이름을 그 리그 안에서 등록함
3. 그 리그에 그 홈·원정 조합의 경기가 베트맨 시작 시각 ±2시간 안에 **딱 하나** 있음
4. 같은 회차의 다른 경기 번호에 이미 연결된 경기가 아님

**연결 상태:**
| 상태 | 뜻 |
| --- | --- |
| `mapped` | 연결됨 |
| `unmatched` | 별칭을 모르거나 후보가 없음. 이름이 비슷한 후보를 보여 줌(자동 연결 안 함) |
| `ambiguous` | 후보가 둘 이상이거나, 같은 회차 다른 번호에 이미 연결됨 |
| `rejected` | 홈·원정이 뒤집혀 있거나, 사람이 연결하지 않기로 함 |

**처음 몇 회차는 사람이 연결합니다.**
```bash
infra/server/edge.sh betman-status --round 2026-81            # 후보(fixture_id) 확인
infra/server/edge.sh betman-map --product proto --round 2026-81 --event 12 --fixture 4567 --learn-aliases
infra/server/edge.sh betman-map --product proto --round 2026-81 --event 13 --reject "우리 리그 아님"
```
- `--learn-aliases`를 붙이면 베트맨 리그·팀 이름을 기억합니다. 다음 회차부터는 같은 이름이 자동으로 연결됩니다.
- 팀 별칭은 리그마다 따로 기억합니다. 같은 약칭이 다른 리그의 다른 팀일 수 있기 때문입니다.
- 시작 시각이 ±2시간보다 크게 다르거나, 같은 회차 다른 번호에 이미 연결된 경기는 사람이 지정해도 거부합니다.
- 사람이 내린 결정은 자동 실행이 덮어쓰지 않습니다.

## 3. 구매 가능 여부

`betman-status --at <시각>`은 그 시각에 각 배당을 **실제로 살 수 있었는지**와, 살 수 없었다면 이유를 보여 줍니다. 손익분기 확률(`1/배당`)도 함께 나옵니다.

다음을 모두 만족해야 구매 가능으로 셉니다.

| 조건 | 아니면 |
| --- | --- |
| 경기가 연결됨 | `not_mapped` |
| 관측 시각이 있는 배당 | `historical_proxy` |
| 관측 시각 ≤ 판단 시각 | `observed_after_decision` |
| 저장 시각 ≤ 판단 시각 | `stored_after_decision` |
| 발매 중 | `sale_suspended`, `sale_closed`, `sale_unknown` |
| 발매 마감 시각을 알고, 그 전 | `sale_close_unknown`, `after_sale_close` |
| 경기 시작 전 | `after_kickoff` |

판단 시각에 저장돼 있던 **가장 최근 배당**만 봅니다. 나중에 들어온 배당이 과거 판단에 쓰이지 않습니다.
